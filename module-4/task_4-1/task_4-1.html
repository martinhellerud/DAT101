  2. In Task 1, we create a static object called "AccountType." Explain what this object is used for and how this type of object can help us in software development.

    3. AccountType holder de faste navnene på kontotypene. Da kan vi skrive AccountType.Saving i stedet for å skrive "Sparekonto" for hånd hver gang, så det blir færre skrivefeil og man trenger bare endre navnet ett sted.

  3. Discuss why we use encapsulation in classes. Why do we want to "hide" code within our class? Explain how we can create "private" and "public" members in a constructor function.

    4. Vi skjuler ting så de ikke kan endres utenfra ved et uhell, f.eks. at noen endrer balance direkte uten å gå gjennom deposit eller withdraw. Private får # foran navnet, som #balance, og kan bare brukes inni klassen. Public er metodene uten #, som deposit(), og de kan brukes utenfra.
